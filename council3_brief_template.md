# Совет 3+1 — decision brief (single-model DeepSeek flash)

## Что это

Три «воркера» и один синтезатор на ОДНОЙ модели (flash). Diversity даёт **роль+слепота+температура**,
не модель. Роли зашиваются в ОДИН prompt, размноженный в 3 слота MoA:

| Роль | Что делает | Что обязана вернуть |
|------|-----------|---------------------|
| W1 «понять» | разбирает материал, собирает ФАКТЫ, отделяет факт от догадки | список фактов + источники/пути, без выводов |
| W2 «атаковать» | ищет дыры, риски, «что сломается первым», контрпримеры | список атак/рисков с конкретным триггером |
| W3 «решить» | даёт решение и самый дешёвый решающий тест | решение + одна проверка + что она НЕ различает |

Синтезатор (агрегатор MoA, он же действующая модель) получает **сырые выводы всех трёх** —
MoA вкладывает reference-outputs ВЕРБАТИМ в свой prompt (не пересказ), агрегатор сам вызывает инструменты
и несёт весь биллинг цикла.

## Формат decision brief (единственный, не вариативный)

```
ЧТО ПРОИСХОДИТ:      <наблюдаемое, без интерпретации, 1-2 строки>
ЧТО ЗНАЕМ:           <факты с доказательством: файл/лог/URL/команда; каждый — проверяемый>
ВЕРОЯТНАЯ ПРИЧИНА:   <гипотеза + почему остальные отброшены; уверенность низкая/средняя/высокая>
ЧТО ДЕЛАЕМ СЕЙЧАС:   1 конкретное действие + путь отката
ЧТО БУДЕТ ОЗНАЧАТЬ
РЕЗУЛЬТАТ ПРОВЕРКИ:  если <исход X> → причина подтверждена, следующий шаг <...>
                     если <исход Y> → причина неверна, гипотеза №2: <...>
```

Правила синтеза (обязательны, иначе brief недействителен):
- Таблица согласие/разногласие/уникальные находки по 3 вердиктам — ПЕРЕД brief.
- Разногласие не сглаживать: писать оба варианта в «ВЕРОЯТНАЯ ПРИЧИНА».
- «ЧТО ДЕЛАЕМ СЕЙЧАС» — ровно одно действие. Два действия = признак незавершённого синтеза.
- Ссылаться на воркеров по номеру (W1/W2/W3) только если вердикт уникален; не приписывать авторство «модели».

## Два сценария вызова — ровно один способ на каждый

### (А) Разовый совет по внешнему материалу — ресёрч/диагностика
```bash
hermes chat -Q --provider moa -m council3 -q "<роли+вопрос+ДОКАЗАТЕЛЬСТВА: конкатенированные логи/файлы/URL>"
# проверить, что 3 воркера реально отработали (сырьё, не пересказ):
cat C:/AI/HERMES/.hermes/moa-traces/<session_id>.jsonl
```
Интерактивный аналог (в сессии): `/moa <prompt>` — одна инструкция, потом возврат к прежней модели.
`/moa` всегда берёт `default_preset`; для council3 использовать `--provider moa -m council3`.

### (Б) Постоянный совет в основном цикле
НЕ нужен. Обоснование: единственная модель одна — «совет» на каждом шаге = 4× вызовов той же flash
на тот же контекст, корреляция ошибок высокая, выигрыш не доказан, а биллинг ×4. Включать только если
появится вторая модель. Крайний дешёвый компромисс — раскомментировать `fanout: "every_n:5"` в пресете,
если позже понадобится (адвайзеры раз в 5 итераций), но по умолчанию `user_turn` (один раз на ход).
